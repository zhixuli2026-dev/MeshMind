# 大规模知识图谱的连接策略

## 问题

知识图谱增长到一定规模后，新增知识点时难以高效地找到应建立连接的位置。全图遍历不可行。

## 两阶段连接策略

### 第一阶段：粗筛 — 向量检索

```
新增知识点 → 生成 embedding → 向量检索图谱中 Top-K 候选节点
```

- 使用 `pgvector` 的向量相似度搜索
- 快速从海量节点中筛选出语义最相似的候选集（如 Top-20）
- 速度快，不受图谱节点总数影响

### 第二阶段：精判 — LLM 语义判断

```
Top-K 候选 + 新知识摘要 → LLM → 判断每对关系
```

LLM 对每一对（新节点，候选节点）判断：

| 判断结果 | 行动 |
|----------|------|
| **重复/基本一样** | 不新增，按维护策略处理（跳过/更新/追加文档） |
| **有明确关系** | 确定关系类型（prerequisite/complementary/derived_from/related_to），建立连接 |
| **矛盾** | 标记 conflict |
| **不相关** | 不建立连接 |

### 为什么先向量后 LLM

- 向量检索：毫秒级从百万节点中筛选候选
- LLM 判断：对少量候选做精确语义判断
- 避免全图遍历，也避免 LLM 面对海量选择

## 连接深度策略

单次入库的搜索范围：

- 初始向量检索 Top-20 候选
- LLM 判断后，如果发现需要扩展，可以从已确认连接的节点再往外搜索一层
- 但默认只做一次向量→LLM 的判断周期
- 深度扩展留给渐进式加载和 Agent 探索时处理

# 活力值衰减引擎

## 核心公式

```
current_vitality = last_vitality × 0.5^(age / half_life)
```

- `last_vitality`: 最近一次 vitality_events 记录的 vitality 值
- `age`: 距离最近一次事件的时间间隔
- `half_life`: 当前有效的半衰期

## 半衰期的唯一影响来源

**只有正面反馈（知识对回答有决定性帮助）才会增加半衰期。**

| 场景 | 对半衰期的影响 |
|------|---------------|
| 知识对回答有决定性帮助 | ✅ 缓慢增长，趋近该类型的半衰期上限 |
| 知识被检索但对回答无用 | 不变 |
| 知识未被访问 | 不变（自然衰减） |

不存在"负面反馈"概念。检索无用≠知识有问题。

## 变化速度

极缓慢。每次正面反馈只调整半衰期的极小比例（~0.1%），以周/月为单位才能感知明显变化。

## 生命周期

```
知识诞生
  → vitality_events INSERT (初始 vitality + 初始 half_life)
  → 随时间流逝，vitality 沿半衰曲线自然衰减
  → 每次被检索：实时计算 current_vitality
  → 被正面反馈：half_life 微增，write vitality_events
  → vitality 降至阈值以下 → 不再被检索
  → 用户手动删除 → is_active=0
```

## 初始值

| 知识类型 | 初始半衰期 | 最大半衰期 | 初始活力值 |
|----------|-----------|-----------|-----------|
| law | ~5 年 | 10 年 | 1.0 |
| rule | ~1.5 年 | 3 年 | 1.0 |
| best_practice | ~2 月 | 6 月 | 1.0 |
| event | ~5 天 | 15 天 | 1.0 |

手动输入的知识初始活力值高于被动提炼的（如 1.2），代表更强的初始存活能力。

## 检索阈值

`current_vitality < 0.1` 的知识不再被检索返回。

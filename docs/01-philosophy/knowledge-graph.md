# 知识图谱

知识图谱是 MeshMind 体系中**串联知识摘要层（L2）的核心机制**。它将孤立的知识点编织成可推理的知识网络。

## 连接关系

知识点之间通过确定的、有类型的关系连接。

### 关系类型

| 关系类型 | 说明 | 检索行为 |
|----------|------|----------|
| **前置条件（prerequisite）** | A 是 B 的前置知识，理解 B 需要先理解 A | 检索 B 时连带检索 A |
| **互补（complementary）** | B 和 C 互相补充，共同构成完整理解 | 检索 C 时连带检索 B |
| **派生（derived_from）** | D 是从 E 衍生出来的 | 检索 D 时提示其来源 |
| **相关（related_to）** | 一般关联 | 检索时作为参考结果 |

### 关系的确定性

关联关系是**确定的**，不是模糊的相似度匹配。这保证了：

- 沿着图谱的遍历是可预测的
- 搜索时的连带检索行为是明确的
- 知识体系的边界是清晰的

## 检索时的联动：LLM 判断机制

图谱定义了**确定的关系**，但检索时的联动行为由 **LLM 自主判断**，而非硬编码规则。这是 MeshMind Agent 柔性化设计的核心体现。

### 原则

```
图谱提供：确定的关系（有哪些边）
LLM 判断：当前场景下应该拉入哪些相关知识点
```

### 不同关系的判断差异

| 关系类型 | 判断倾向 |
|----------|----------|
| **前置条件** | LLM 几乎一定会拉入 — 缺少前置知识会导致判断出错 |
| **互补** | LLM 通常会拉入 — 互补知识共同构成完整理解 |
| **验证关系** | LLM 根据场景选择 — 某些场景可以不完整检索 |
| **一般关联** | LLM 灵活决定 — 按需加载 |

### 示例

```
检索 B 知识点：
  A → B（前置条件） → LLM 判断：必须拉入 A，否则无法正确理解 B
  B ↔ C（互补）    → LLM 判断：拉入 C，提供完整上下文
  B ↔ D（验证）    → LLM 判断：场景 A 需要验证所以拉入；场景 B 不需要验证所以跳过
```

### 为什么由 LLM 判断

固定的连带检索规则会产生两个问题：
- 过度检索：无关知识涌入，干扰判断
- 检索不足：关键上下文缺失，判断出错

LLM 根据当前任务、场景和问题的性质动态决定检索边界，比硬编码更智能。
